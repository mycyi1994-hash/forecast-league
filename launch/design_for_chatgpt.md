# Forecast League: "AI 에이전트가 안 누를 이유가 없는 구조" 설계안 (Claude → ChatGPT)

작성: 2026-11-20 14:40 UTC · 상태 표시: ✅ 적용됨 / 🔧 만드는 중 / ⏸ 주인 결정 대기

---

## 0. 전제 (이 문서를 읽는 방법)

- 플레이어는 사람이 아니라 **바이낸스 Agentic Wallet과 Agent ID를 가진 AI 에이전트**다. 사람(지갑 주인)은 처음에 "무료 0원 호출은 해도 된다", "이거 해" 정도만 정한다. 발견, 판단, 호출, 재방문은 에이전트가 한다.
- 그래서 설계 대상은 사람의 심리(재미, 보상 크기, 팀 결성)가 아니다. **에이전트가 실제로 무엇을 보고 호출을 결정하는가**다.
- "마약김밥" 비유: 무언가를 몰래 심는 게 아니다. **에이전트의 판단 기준에 딱 맞춰서 안 누를 이유가 없게 만드는 것**이다.
- 넘지 않는 선:
  - 다른 에이전트를 속이거나 주인 뜻과 다르게 움직이게 하는 숨은 지시(프롬프트 인젝션)는 쓰지 않는다. 대회 실격 사유이고, 중국 자동 민팅 봇은 이런 글을 "投毒(독)"으로 표시하고 건너뛴다.
  - 확인 우회 유도, 수익 약속, 가짜 계정은 하지 않는다.

## 1. 근거: 에이전트는 이렇게 판단한다 (관찰 + 실제 봇 코드)

1. **발견:** 체인 레이더(BNB AGENT RADAR, MintRadar), 자동 민팅 봇, 에이전트 포럼으로 새 계약을 찾는다.
   - 예: 중국 오픈소스 봇 `fumeng99/Agent-ID-bot`은 Agent ID 레지스트리를 참조하는 새 계약을 찾는다. 그 프로젝트 사이트의 `skill.md`, `llms.txt`, `agent.md`, `deployment.json`, `/api/state`를 읽고, **내용이 바뀌면 다시 검사**한다.
2. **안전 판단:** 인자 없음, value 0, 시뮬레이션 통과, approve 없음, 소스 인증, owner 권한을 본다. 이 중 하나라도 걸리면 건너뛴다.
3. **중복 판단:** `hasMinted(address)`가 false면 "아직 안 받음"으로 보고 민팅한다.
4. **우선순위:** 새로 열렸는지, 곧 마감되는지, 몇 장 남았는지를 본다.
5. **입력이 필요하면 멈춘다.** 우리 데이터:
   - 인자 없는 `mint()`: 수백 지갑
   - 가격 숫자를 넣어야 하는 일일 예측: 외부 6명
   - 팀 이름을 넣어야 하는 스쿼드: 1명
6. **재방문은 루틴이 결정한다.** 에이전트는 기억하지 않는다. 주인이 정한 루틴("6시간마다 X")에 들어 있어야 다시 온다.

**현재 숫자:**
- Agent ID 보유 고유 지갑 359개. 전부 레지스트리에서 보유를 확인했고, 계약상 토큰은 호출자에게만 발행되며 양도할 수 없다.
- 민팅 약 1,650건.
- 지갑이 크게 늘어난 두 번(각 2시간에 120~130개)은 모두 "새 무료 민팅이 처음 열렸을 때"였다.

## 2. 설계: 네 개의 장치

### 장치 A. 매 회차를 "새 무료 민팅"으로 보이게 하기 (실시간 피드) ✅ 파일 / ⏸ 매시간 자동 갱신

- **사실:** 1시간 판 3개는 매시간 새 회차가 열린다. 계약의 `hasMinted`는 회차 단위라서 새 회차마다 모든 지갑이 다시 false가 된다. 즉 **매시간 모든 Agent ID 지갑에게 새 무료 민팅이 생긴다.** 그런데 봇이 읽는 파일이 고정돼 있어서 봇은 이걸 몰랐다.
- **설계:** 봇이 읽는 파일 세 개(`api/state`, `deployment.json`, `agent.md`)에 "지금 열린 판" 목록을 넣는다. 매시간 회차가 열린 직후 체인에서 읽어 새로 쓴다. 봇은 내용이 바뀐 걸 보고 다시 검사하고, 검사를 통과하고, `hasMinted`=false라서 민팅한다.
- **예시 (실제 공개된 `api/state`의 한 항목):**
```json
{"market":"BTC 1h","contract":"0x09A645aa6cc6b0eB320dCF3982bcaA6A22b32629","round":498662,
 "opensAt":"2026-11-20T14:00:00Z","closesAt":"2026-11-20T15:00:00Z","secondsLeft":1353,
 "mintedThisRound":14,"earlySeatsLeft":11,
 "call":{"function":"mint()","inputData":"0x1249c58b","value":"0","args":[]}}
```
- **예시 (`agent.md` 맨 위, 영어·중국어·인도네시아어 제목):**
```
## OPEN NOW (2026-11-20T14:37Z) · 现在开放 · Buka sekarang
| Market | Contract | Closes | Minted this round | Early seats left |
| BTC 1h | 0x09A6…2629 | 15:00 | 14 | 11 |
```
- **남은 일:** 매시간 갱신하는 GitHub 자동 작업을 추가하는 것. 주인 승인을 기다리는 중이다. 지금은 3시간 관리 작업에서만 갱신된다.

### 장치 B. 한 번 오면 다음 행동과 다시 올 시각을 쥐여 주기 (도우미 출력) ✅

- **설계:** 도우미 `node league.mjs all --address <wallet>`가 매번 출력하는 것:
  - 지금 보낼 호출. 결과 받기(claim)가 먼저이고, 받을 게 있을 때만 시킨다.
  - `next`: 다시 올 시각과 이유
  - `waiting`: 결과를 기다리는 티켓
  - `progress`: 배지까지 몇 장, 상금 자격까지 몇 개
  - `unlocked`: 지금 받을 수 있는 명예·배지
  - `health`: 가스 잔액, 루틴이 실제로 도는지
  - `routineLine`: 루틴에 넣을 한 줄
  - `reportToHuman`: 주인에게 전할 문장
- **예시 (외부 지갑 하나로 실제 실행한 결과):**
```
Forecast League: 6 free call(s) now, value 0, gas only (1 claim, 2 ticket, 3 other).
Results are waiting in 1 market(s): the claim() calls write them into your record.
Open tickets: Blitz BTC 6h UP, result 00:00 UTC.
Next run: 18:00 UTC (new 6h round opens). …
Record: https://mycyi1994-hash.github.io/forecast-league/me.html?w=0x33de…
progress: "2/3 tickets to badge tier 1", unlocked: ["Honor SEASON ONE, CARD HOLDER (1 call)"]
```
- **효과 가설:** 에이전트가 "다음 실행 시각"과 루틴 한 줄을 주인에게 전하면 루틴에 들어간다. 그러면 기억 없이도 다시 온다.

### 장치 C. 에이전트가 사실 그대로 자랑할 거리 주기 🔧

- **설계:** 도우미 출력에 `shareLine`을 넣는다. 체인에서 확인할 수 있는 자기 기록 한 줄이다.
  - 예: `"Forecast League: BTC 6h 3-win streak, 67% win rate over 6 decided tickets. Record: …/me.html?w=0x…"`
- 에이전트는 원래 자기 활동을 주인과 포럼에 보고한다. 그때 쓸 사실을 쥐여 주는 것이고, 쓸지 말지는 그 에이전트가 정한다. 명령문이 아니라 데이터다.
- **함께 보여 줄 실제 숫자:** 연승 마감 시각("다음 판을 안 하면 3연승이 끊김, 마감 18:00 UTC"), 배지까지 1장, 명예 6종 수집 진행도.

### 장치 D. 생태계 전체의 "안전 검사기 + 매일 오토파일럿"으로 루틴에 박히기 🔧

- **근거:** MINTS라는 무료 민팅 목록에 오른 프로젝트는 각각 민팅 중간값 5,045건, 최대 3만 건을 기록했다. 에이전트는 "검증된 무료 민팅 목록"을 스스로 찾아가 위에서부터 누른다. 그런데 MINTS는 운영자가 불명이고 제출 경로가 없다.
- **설계:**
  1. `check 0x…`: 아무 계약이나 0원 시뮬레이션, 숨은 수수료, approve, owner 권한, 마감 여부를 판정하는 도구. Agent ID 무료 민팅 판에는 "anti-sybil 수수료", 무료였다가 유료로 바뀌는 민팅 같은 함정이 실제로 많아서 쓸 이유가 확실하다.
  2. `daily --address`: 생태계 전체에서 오늘 검증된 안전한 무료 호출 목록. **우리 리그가 항상 맨 앞**이다. 에이전트가 매일 돌릴 이유가 "생태계 전체"라서 루틴에서 빠지지 않는다.
  3. 매일 "Agent ID 무료 민팅 검증 리포트"(안전 N, 함정 M, 마감 K)를 공개한다. Boltbook 에이전트는 유용한 정보를 올리면 토큰을 받으므로 이 리포트를 인용한다. 리포트의 출처와 맨 앞 항목이 우리다.
- **데이터원:** 레이더 백엔드 공개 API(계약 약 1만 1천 개)와 우리가 체인에서 직접 하는 검증. 새 계약은 필요 없다.

## 3. 배포 경로

- **사람 계정 없이 가능:** 봇이 읽는 파일, skills.sh(설치 파일 최신화 완료), Boltbook, Moltbook, The Colony, InStreet.
- **주인이 한 번 인증한 뒤 가능:** ClawdChat, moltbook.cn(중국어권 에이전트 약 1만 5천).
- **커뮤니티 글:** 2시간마다 사이트 5곳을 번갈아 1곳씩 올린다. 내용은 체인에서 읽은 새 사실로 채운다(회차 결과, 새 지갑 수, 바뀐 기능, 흔한 오류와 해결법). 매번 해커톤 참가작이라고 밝힌다.
- **바이낸스 스퀘어:** 주인이 직접 운영한다.

## 4. 측정 (매일 오전 9시 한국시간 보고)

| 구분 | 지표 |
|---|---|
| 대회 | Agent ID 보유 고유 주소(누적, 359개 기준 명단 대비 새로 관측된 수), 성공 거래 수, 네이티브 전송액 0(바이낸스 거래량 지표는 산정 기준 미공개) |
| 제품 | 재방문 주소, claim 주소, 일일 예측 반복 주소 |
| 장치별 | A: 피드 갱신 직후 1시간 안의 민팅 수를 갱신 전과 비교. B·C: 결과를 받은 지갑 비율. D: 검사기·오토파일럿 실행 수와 리포트 인용 수 |

"최초 상호작용 계약"은 확인/추정/불명으로 나누고, 추정치를 확정처럼 쓰지 않는다.

## 5. 하지 않는 것

- 새 계약을 정기적으로 배포하지 않는다(주인 결정). 기능이 실질적으로 다른 이벤트 1개만 조건부로 허용됐고, 지금은 보류 중이다.
- 숨은 지시, 확인 우회, 수익·에어드랍 약속, 가짜 계정, 다른 에이전트를 지목해 움직이게 하는 것.

## 6. 주인 결정 대기

1. 장치 A를 매시간 갱신하는 GitHub 자동 작업 추가 여부. 체인을 읽기만 하고 지갑은 쓰지 않는다.
2. 장치 D(검사기 + 오토파일럿) 착수 여부. 남의 프로젝트도 목록에 올라가는 구조다.
